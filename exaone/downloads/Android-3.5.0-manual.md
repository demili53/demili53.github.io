# 엑사원 AI 모바일 3.5.0

Android 8.0 이상에서 실행하는 네이티브 Android 앱입니다. Google Play 등록은 보류하고 직접 설치용 APK를 제작합니다.

## 사용

1. APK를 Android 휴대폰에 복사하여 설치합니다.
2. 첫 화면의 데이터 전송 안내를 확인하고 자신의 EXAONE API 키를 설정합니다.
3. 대화만 하려면 바로 메시지를 보냅니다. 파일 작업을 하려면 **작업 폴더**에서 전용 폴더를 선택합니다.
4. 파일 저장 시 전체 내용 미리보기에서 승인하거나 거절합니다. 답변 아래 **답변을 파일로 저장**으로 직접 내보낼 수도 있습니다.

앱에는 개발자의 API 키가 들어 있지 않습니다. 인터넷 연결과 유효한 개인 EXAONE API 키가 필요합니다. API 키는 Android Keystore의 AES-GCM으로 암호화되며 앱 백업은 비활성화했습니다. 대화 원본과 도구 결과는 앱 전용 저장 공간에 보관하여 재실행 후 복원합니다. 요약 캐시는 같은 대화에서 재사용하며 앱 종료 후에는 필요할 때 다시 생성합니다. 대화 기록은 API 키와 별도의 저장 파일이며, 대화 본문 자체를 추가 암호화하는 기능은 아닙니다. 새 대화로 기록을 초기화할 수 있고 사용자가 저장한 작업 파일은 유지됩니다.

설정에서 API 키 삭제 및 개인정보 안내를 확인할 수 있습니다. 작업 폴더 권한과 모든 앱 데이터를 지우려면 Android 설정에서 앱 데이터를 삭제하세요.

## API 키 발급·등록

앱의 첫 화면 또는 **설정 → API 키 발급·등록 안내**에서 순서를 확인할 수 있습니다.

1. [EXAONE 공식 페이지](https://docs.exaone.ai/ko/docs/overview)의 **API Key 발급하기**로 이동합니다.
2. 공식 사이트에서 직접 로그인하고 본인의 키를 발급받습니다.
3. 앱의 **설정 → 새 API 키 입력**에 키 값만 붙여 넣습니다. `Bearer`나 따옴표는 넣지 않습니다.
4. **키 저장**을 누르고 대화를 시작합니다. 키 저장은 이 기기에 보관하는 동작이며, 서버 인증은 실제 메시지를 보낼 때 확인됩니다.

401은 키 인증 실패, 429는 서버 요청 제한을 나타냅니다. 429에는 잔여 호출이 양수인 응답도 있을 수 있어 앱은 실제 헤더 정보를 함께 표시합니다. 키는 채팅·스크린샷·다른 사람에게 공유하지 마세요. 공식 기준은 [인증 안내](https://docs.exaone.ai/ko/docs/authentication), [오류 코드](https://docs.exaone.ai/ko/docs/error-codes), [호출 제한](https://docs.exaone.ai/ko/docs/rate-limits)에서 확인할 수 있습니다.

## 기능

- K-EXAONE 2.5 대화, 빠르게/균형 있게/깊게 추론 설정
- 시스템 폴더 선택기를 통한 폴더 조회, UTF-8 텍스트 읽기·쓰기 (최대 100KB)
- 파일 저장 사전 승인, 작업 중지, 새 대화, 답변 텍스트 내보내기
- 대화 기록 복원, 파일 도구 실행 전후 체크포인트, 결과 불명확 작업 확인
- 전송할 대화가 50,000자를 넘으면 지난 대화를 요약하고 최신 요청과 도구 결과 묶음 보존
- 같은 앱 프로세스의 API 요청 시작 간격 최소 1초, 대화·요약·재시도에 공통 적용
- 429 응답의 초·분·일 한도와 잔여 호출 표시, 서버 대기 시간 준수, 불필요한 재시도 중단
- API 응답 대기 최대 30분, 작업 취소 시 대기 요청 전송 중단
- 전체 저장소 접근 권한, 광고 SDK, 분석 SDK를 사용하지 않음

3.5.0은 Windows 버전의 공통 대화·통신 개선을 Android에 반영한 버전입니다. Android 화면과 파일 도구는 별도 구현입니다. Chrome DevTools 조작, PowerShell·터미널, MCP, 예약 작업, 웹 검색, PDF 첨부, 여러 대화 관리, 스트리밍 및 후속 요청 대기열은 포함하지 않습니다. API 요청 간격은 이 앱 프로세스에 적용되며 같은 키를 사용하는 다른 프로그램의 호출까지 조정하지 않습니다.

파일 도구 실행 결과가 불명확하거나 저장 기록을 읽지 못하면 기록과 실제 파일을 먼저 확인해야 합니다. 실행 여부 확인 없이 변경을 자동 반복하지 않습니다. 앱은 파일 변경과 대화 저장을 하나의 원자적 작업으로 묶을 수 없으므로 정확히 한 번의 실행을 보장하지는 않습니다.

## 빌드

JDK 17, Gradle 8.14.3, Android SDK 36이 필요합니다. Android Studio에서 이 `mobile` 폴더를 열거나 Gradle을 사용합니다.

```text
gradle assembleDebug testDebugUnitTest lintDebug
gradle connectedDebugAndroidTest
```

SDK 위치는 로컬 `local.properties`의 `sdk.dir`로 설정합니다. 결과는 `app/build/outputs/apk/debug/app-debug.apk`입니다. 직접 설치용 APK는 개발용 서명입니다. 기존 0.1.0과 같은 앱 식별자와 서명으로 빌드하면 업데이트 설치할 수 있습니다. Google Play 배포는 별도 작업입니다.

## 소스

`MainActivity`는 모바일 화면과 저장 승인을, `ExaoneClient`와 `AgentProtocol`은 API 및 도구 반복을, `Workspace`는 선택한 폴더의 파일 접근을, `KeyVault`는 암호화 키 저장을 담당합니다.
